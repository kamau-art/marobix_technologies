2. PAGE-BY-PAGE MVP SPEC
------------------------
2.1 Home
- Header + sticky nav with "Get a Quote" CTA
- Hero (headline, subhead, 2 CTAs, trust badges: "50+ projects", "Clients in X countries")
- Logo strip / trusted-by row (optional)
- Services grid (8 cards, icon + 1-line blurb -> service page)
- Featured portfolio (6 cards, filter by category)
- Why Marobix (3-4 value props with icons)
- Testimonial carousel (3+)
- Process strip: Discover -> Design -> Build -> Launch -> Support
- CTA banner ("Ready to build something great?")
- Footer
Primary CTA: "Get a Free Quote" -> /contact
Desktop: 12-col grid, hero full-bleed, services 4 cols, portfolio 3 cols, max width 1280px.
Mobile: single col; hero stacked; services 1 col (2 col >=480px); portfolio + testimonials swipe carousels.
Newsletter form: email required, valid regex, inline error, success toast.

2.2 About
Hero statement -> Company story (2-3 paras) -> Mission/Vision -> Team grid (optional) -> Stats bar -> CTA "Work with us" -> /contact.

2.3 Services (Overview)
Intro hero -> Services grid (8+ cards) -> comparison note -> CTA.
8 services: Website Development, Ecommerce Development, POS System Development, IT Sourcing & Procurement, Data Backup & Recovery, AI Integrations, Cloud & Hosting Setup, IT Support & Maintenance.

2.4 Service Detail (template /services/[slug])
Breadcrumb -> Hero (name, value prop, CTA) -> What's included (bullets) -> Process (3-5 steps) -> Related portfolio (2-3 by tag) -> Pricing hint ("Starting from KES X" or "Custom quote") -> FAQ accordion (3-5 Qs) -> CTA banner.
CTA -> /contact?service={slug} pre-fills lead form.

2.5 Portfolio (Gallery)
Hero + filter/tag bar (Web, Ecommerce, POS, AI, IT Sourcing) -> grid (image, title, category tag, 1-line outcome) -> Load more / pagination -> CTA.
Desktop 3-col masonry/grid; mobile 1-col, chips horizontal-scroll.

2.6 Case Study (template /portfolio/[slug])
Hero image + title + client + tags -> Overview (client, industry, timeline, tech stack badges) -> Challenge -> Solution (2-3 screenshots) -> Results (metric callouts) -> Testimonial -> Related projects -> CTA.

2.7 Pricing / Plans (productized only)
Hero -> 3-tier cards (Starter / Business / Enterprise) -> feature comparison table -> note: IT sourcing/POS/custom AI is quote-based -> FAQ -> CTA.
Recommendation implemented: publish only productized offerings (e.g. "Basic Business Website — from KES 35,000"), route everything else to "Get a Quote".

2.8 Checkout / Payments
Order summary (service/plan, price, currency) -> Customer details form -> Payment method selector (M-Pesa / Card via Stripe / PayPal) -> Payment action -> Confirmation.
Fields: Full name (req), Email (req, valid), Phone (req for M-Pesa; E.164 or 07XXXXXXXX), Company (opt), Billing address (req for card), Order notes (opt, max 500).
Validation: required checks, email regex, phone regex, amount must match selected plan server-side.
Security: all amount/currency re-validated server-side before creating payment intent — never trust client payload.

2.9 Contact / Get a Quote
Hero -> Contact form -> Direct contact info (email, phone, WhatsApp, address) -> Map embed (optional) -> Social links.
Fields: Name (req), Email (req), Phone (opt), Company (opt), Service interested (dropdown, pre-filled via ?service=), Budget range (opt), Message (req, min 10 max 2000), Consent checkbox (req, GDPR/DPA).
Validation: regex, honeypot + reCAPTCHA-ready, consent required.

2.10 Blog (Index + Article)
Index: hero -> filter by category -> card grid (image, title, excerpt, date, read time) -> pagination.
Article: title, hero image, author + date, rich-text body (CMS-rendered), share buttons, related articles, newsletter CTA.
MVP: no comments.

2.11 Careers (optional MVP)
Intro + list of open roles (title, type, location, Apply mailto) + culture blurb.

2.12 Legal (Privacy Policy & Terms)
Static CMS-editable pages. Reference Kenya DPA 2019, data controller identity, data collected, third-party processors (M-Pesa/Stripe/PayPal), user rights, cookie/consent banner reference, contact for data requests.
NOTE: must be drafted/reviewed by a lawyer before launch — content is placeholder, treated as CMS content.

3. UI COMPONENT LIBRARY — STATES & A11Y
--------------------------------------
Header: sticky -> solid bg after scroll threshold; mobile hamburger slide-in drawer; focus trap; aria-expanded.
Hero: real <h1>; 4.5:1 contrast on overlay text.
Service Card: hover lift + shadow; whole card = single focusable <a>; no nested interactive elements.
Portfolio Card: hover image zoom + overlay tag; click -> case study; descriptive alt text.
Testimonial Carousel: auto-rotate 6s, pause on hover/focus, arrows + dots, pause button; dots aria-label="Go to slide N".
Pricing Card: "recommended" tier highlighted; table structure; checkmarks aria-label="included".
Contact Form: inline validation on blur, submit disabled until valid, loading spinner, success/error toast; labels for/id, errors aria-describedby, aria-live="polite".
Newsletter Form: same as contact, compact.
Footer: multi-column, accordion on mobile; <footer> landmark; <nav aria-label="Footer">.
Buttons: primary/secondary/ghost; hover/active/disabled/loading; min 44x44px; disabled uses aria-disabled.
Banners/Alerts: success/error/info variants, dismissible; role="alert" or role="status".
Chips/Tags: toggle active state; aria-pressed.
Iconography: Lucide, consistent stroke width; decorative aria-hidden, functional aria-label.
Badges: tech-stack, "New"; text-based, not color-only.
